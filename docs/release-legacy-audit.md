# Legacy release safeguard audit — round 9

Audited 2026-10-20. The original inventory contains 28 package workflows; this pass reads all 28 plus the now-available pm-memory copy (29 total). All source workflow files were clean. The upstream CLI is outside this reusable package port. [Snapshot receipts](release-legacy-audit.json) record each checkout commit, workflow SHA-256 and the job/name/line/body hash of every selected step: 449 occurrences, 138 distinct executable bodies. Selection includes every retry loop and every install, decide, changelog, verify, merge, pack, publish, tag, recovery, completeness and alert step. The comparison includes step guards, ordering and job permissions, not only matching comments.

Comments about incidents, caches, propagation, retries, races, timeouts and stale state were grouped by safeguard below; repository-name-only duplicates share a row. Older weaker implementations are identified where the newer fix supersedes them. Package-specific differences continue through explicit hooks; no consumer workflow changes here.

## Regression evidence

The Bun contract requires both the fresh runner-temp cache export and the subsequent cache clear before bun add inside the loop; comments and setup outside the loop cannot satisfy it. Behavioral tests cover midnight resumption and tag spelling equivalence, the actual CI jq selector, and the publish shell with synthetic registry boundaries: delayed successful publication without republishing, the final visibility read, different bytes from the same commit, and unavailable metadata. The audit contract requires scheduling after recovery and release without a should-release/success guard and connects its failures to alerting. Revert results and full npm/Bun gate counts are recorded on ops-reusable-daily-release and PR #183.
