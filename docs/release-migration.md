# Release continuation and fleet migration

The pm-ops pilot is .github/workflows/release.yml: a local call to the shared workflow at the same trusted commit, daily at 03:23 UTC and reconciliation-only at minute 41 hourly. No other package is modified. The existing npm trusted-publisher caller filename remains release.yml. Live publication is deliberately not exercised by this implementation PR.

## Event and state contract

Preparation records `.github/pm-release-candidate.json` (version, base SHA, run/attempt and configuration digest), verifies it together with package metadata through npm/Bun and package-owned changelog hooks, then commits those verified files so even unchanged version metadata has a distinct protected PR, captures one package tarball and notes from that commit, uploads an immutable Actions artifact for 90 days, and writes a versioned pm-ops-candidate-v1 receipt into the verified bot PR BEFORE requesting protected squash auto-merge. The receipt records repository/default branch, exact base/head/tree, version/tag/package, SHA-256 and SHA-512 tarball digests, notes digest, caller configuration digest, source run/attempt, exact trusted pm-ops tools SHA and immutable artifact ID. Bot PR body ownership is insufficient by itself: publication compares the receipt byte-for-byte with candidate.json from the trusted main preparation run.

The hourly schedule and daily catch-up discover that receipt even if GITHUB_TOKEN suppresses the merge push event. An empty hourly run executes one short job with a five-minute upper bound and no npm install. Open PRs retain their receipt without waiting. Caller input changes also retire open or merged intent only after live absence of attempts, tags, Releases and the old package coordinate is established. Open PR auto-merge is disabled before retirement; changed project paths are not used to inspect old release source. A differing bot attempt fingerprint is an explicit refusal, so a changed receipt cannot hide an ambiguous publication. An unpublished behind-base squash merge with a changed parent/tree/version retires its receipt on a fresh current-main run only when no publish attempt, tag, Release or registry artifact exists. Any publication evidence keeps the receipt for operator reconciliation. A stale base permits daily refresh; the workflow disables existing auto-merge before refreshing the leased head and records the successor candidate before re-enabling it. Duplicate schedules/manual retries are serialized by the reusable daily-release concurrency group, with at most one pending candidate admitted per repository. Multiple pending receipts are refused explicitly. This is repository admission; account-wide capacity reservation/staggering remains with the existing fleet owner.

Tool bootstrapping uses the recorded trusted source checkout, its committed planner and locked planner dependencies with lifecycle scripts disabled. Provenance verification installs a separate private runtime only when needed; its overrides apply at that installation root and CI audits its lockfile. It never requests the source checkout's package version from npm, so an unpublished version on main cannot prevent recovery. Legacy receipts derive the tools commit from the authenticated source run's referenced workflows. Caller configuration hashes use deterministic code-unit ordering, preserving existing English-host receipts across runner locales.

Before publication, continuation re-reads repository/default branch, same-repository bot PR and release date branch, exact head and squash-merge parents/tree, successful prepare job from the exact recorded main run attempt and immutable artifact identity, the complete required-context/app policy and exact-head checks/reviews, caller inputs, package coordinate, remote tag/Release and live registry provenance. Registry acceptance authenticates the Sigstore signature, Fulcio executing-workflow identity from the source run and transparency evidence, independently binds the authenticated certificate source repository/commit/ref, then binds the signed repository, caller workflow, default-branch ref, merged commit and tarball digest; decoded JSON alone cannot authorize repair. Protection policy comes from the [contents-read branch endpoint](https://docs.github.com/en/rest/branches/branches#get-a-branch), including the complete contexts and numeric app IDs. The exact-head GraphQL rollup uses the same numeric app IDs and its review decision; it never reads administration-only branchProtectionRule. Active rulesets are explicitly refused until a complete ruleset adapter is reviewed. Missing, skipped, failed, truncated or unreadable proof refuses publication. A missing classic branch-protection policy is an explicit refusal; packages using a different ruleset model need a reviewed adapter before migration. The publisher downloads by immutable artifact ID and verifies candidate, tarball and notes bytes before using any package hook. New npm publication requires workflow trigger SHA to equal the merged default-branch commit for npm provenance. If main advances before publication, the probe reports `stranded`. Only a run triggered at current main can retire a candidate with no publication attempt, no registry coordinate and no tag/Release. It comments, preserves the complete receipt under `pm-ops-retired-candidate-v1`, confirms the write, and admits fresh daily preparation. Old deliveries retain the active intent. Already attested npm publication can repair its exact tag/Release after main advances, without publishing npm again. Ambiguous attempts and partial or disagreeing remote state remain explicit refusals.

The publisher records a bot attempt comment before npm publish, publishes ./release-artifact/package.tgz with OIDC/provenance and disabled lifecycle scripts, and verifies registry-served source/digest agreement before completing tag/Release creation. Verified npm publication resumes tag/Release repair without publishing again. A recorded attempt followed by registry absence is ambiguous: later hourly reads can reconcile visibility, but must not automatically repeat publication. A pre-request crash can therefore need a maintainer to inspect and authorize recovery. A completed npm/tag/Release triplet clears the pending receipt only after fresh verification and durable completion of any configured post-release hook. A bot journal records hook attempt and completion. Recovery executes a never-started hook once, skips a completed hook, and preserves an interrupted attempt as an explicit refusal requiring operator verification. Expired artifacts, failed preparation jobs, changed inputs or inconsistent publication evidence produce an explicit refusal and preserve the receipt. Optional extra publication hooks remain package-owned and need their own retry safety when a fleet package uses them.

The reconcile job retains read-only contents access and uses pull-request write permission only to retire the verified unpublished intent. A same-named retired branch is reused only after re-reading its bot-owned same-repository merged PR and exact retired head; the push retains its force-with-lease. Superseded receipts are retired and confirmed before close, with a comment naming the successor; retirement and close failures fail visibly.

Daily cap checks use live GitHub Release timestamps and npm publication timestamps in the configured timezone, including releases that resume an older version. Recovery of an already verified publication does not consume another npm publication. The old runner-held 30-minute merge deadline and stale workflow-approval timeout diagnosis are gone. A single current-head CI approval attempt may run on each hourly pass; an actual approval refusal remains visible without a timeout claim.

GitHub documents [GITHUB_TOKEN event suppression](https://docs.github.com/en/actions/concepts/security/github_token#when-github_token-triggers-workflow-runs) and [default-branch scheduled workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). npm documents that [reusable trusted publishing validates the caller workflow identity](https://docs.npmjs.com/trusted-publishers/). Keep the existing caller filename and obtain the normal explicit approval for any publisher identity/permission changes.

## Exact caller template

After the orchestrator releases this change, replace BOTH the zero SHA and tag comment below with that canonical tag's peeled commit and exact tag spelling. No released SHA containing this implementation exists during this PR. Dependabot's github-actions ecosystem owns later SHA updates. Preserve each package's existing daily slot and approval expression; stagger new hourly slots during the controlled fleet wave. Do not add a caller-level daily-release concurrency group.

```yaml
name: Daily Release
on:
  schedule:
    - cron: "23 3 * * *"
    - cron: "41 * * * *"
  workflow_dispatch:
    inputs:
      retire-unpublished:
        description: Retire only owned untouched unpublished intent
        type: boolean
        default: false
permissions: {}
jobs:
  release:
    permissions:
      contents: write
      pull-requests: write
      actions: write
      checks: read
      id-token: write
      issues: write
    uses: unbraind/pm-ops/.github/workflows/daily-release.yml@0000000000000000000000000000000000000000 # REPLACE_WITH_CANONICAL_TAG
    with:
      # Keep this comparison in sync with the hourly cron above when staggering schedules.
      reconcile-only: ${{ (github.event_name == 'schedule' && github.event.schedule == '41 * * * *') || inputs.retire-unpublished == true }}
      retire-unpublished: ${{ github.event_name == 'workflow_dispatch' && inputs.retire-unpublished == true }}
```

Keep defaults npm-project-dir: '.', node-version: 22.18.0, release-timezone: Europe/Vienna, build-script: build, verify-script: release:check, changelog-script: changelog:full, changelog-check-script: changelog:check, notes-script: release:notes, npm-publish: true and bun-verify: true unless the inventory below names an exception. Existing scripts retain pm-changelog as the generator; no shared changelog implementation replaces them. Add missing named hooks inside each future package migration, then replace its local workflow-shape tests with caller/input assertions while retaining its gate names. Upgrade its pm-ops dependency through Dependabot before using the new caller checker. Checks-read is the additional permission needed to inspect protected-check evidence; the reusable jobs reduce the caller ceiling individually.

## Rollout, rollback and evidence still required

This PR uses Refs #249. Before a wider rollout the orchestrator must complete a real normal-npm pilot's event route, protected auto-merge and npm trusted-publisher identity checks, then the representative Rust/Postgres/self-host cases. This task does not authorize publication, new credentials, publisher setting changes, merges or edits to other repositories.

The existing fleet owner retains account-wide capacity snapshots/reservations, simultaneous-dispatcher and stale/partial-snapshot admission tests, bounded cross-repository pending work, staggered waves, preservation of current-head CI/push/schedule/release runs, and the account recheck one hour after the release window. Do not call repository serialization an account-wide admission policy.

Measure runner-held PR-wait minutes (source objective: zero), queue time, actual execution time and release completion separately. No live timing or core feedback-time improvement is claimed from fixtures.

Rollback the local caller migration through a reviewed revert. Keep candidate artifacts and receipts. During rollback leave `release-enabled: true` and set `reconcile-only: true` on every caller invocation; setting `release-enabled: false` also disables reconciliation and strands pending receipts. For a candidate blocked by non-success protection evidence, an operator may additionally request `retire-unpublished: true`. This supports owned open PRs, manually closed unmerged PRs and merged PRs, including expired artifacts or deleted preparation runs. It rechecks the exact bot-owned same-repository branch/head and requires live absence of the npm coordinate, tag, Release, publication attempt and post-hook journal. Missing preparation evidence can permit cancellation only; it never permits publication. An open PR has auto-merge disabled, its receipt durably retired, and is then closed with a confirmed read-back. Fresh preparation may reuse that closed unmerged branch only when its exact head and the recorded operator or verified source/configuration retirement still match; the new verified push retains its head lease. Ordinary closed unmerged branches remain refused. Reset the operator input after recovery. Never fall back to publishing from an old PR artifact, force a tag, remove an ambiguous publication journal or bypass the protection checks. If the old workflow must be restored, reconcile its outstanding intent first so two release implementations cannot race.

Before migrating each remaining caller, record its bot-created issue/PR count and active receipt count using the REST creator filter. Discovery uses that direct REST index rather than a search index or all pull-request history; creation order prevents ordinary updates from moving records between pages; only receipt-bearing PRs are hydrated, and the probe passes its freshly read PR number to verification instead of scanning twice. Both paths refuse incomplete pagination at 100 full pages. Repositories approaching that bound require an explicit durable index before migration. On 2026-11-06 the read-only pm-ops pilot preflight returned 58 bot-created records in one page; counts for other packages remain required in their own migration PRs.

```sh
counts=$(gh api --paginate 'repos/OWNER/REPO/issues?state=all&creator=github-actions%5Bbot%5D&per_page=100' --jq 'length') && printf '%s\n' "$counts" | awk '{ sum += $1 } END { print sum+0 }'
gh api --paginate 'repos/OWNER/REPO/issues?state=all&creator=github-actions%5Bbot%5D&per_page=100' --jq '.[] | select(.pull_request and ((.body // "") | contains("<!-- pm-ops-candidate-v1"))) | .number'
```

The [repository issues endpoint](https://docs.github.com/en/rest/issues/issues#list-repository-issues) includes PRs and supports the creator filter. The reconcile and publishing jobs request only issues-read for this discovery operation.
